# دليل استخدام Presidential Governance

الإصدار **1.1.0-preview.4** تجريبي. المهارة تساعد الوكيل على إدارة العمل من فهم المطلوب إلى التخطيط والتنفيذ والتحقق، مع الحفاظ على قرارات المشروع وصلاحيات المستخدم. حجم الإجراءات يتناسب مع المهمة.

## التنزيل والتثبيت

من صفحة المستودع على GitHub اختر **Code → Download ZIP**، ثم فك الضغط وثبّت **المجلد كاملًا** وفق [دليل التثبيت](INSTALLATION.md). في Codex يكون مسار المستخدم `~/.agents/skills/presidential-governance`، ويجب أن يوجد `SKILL.md` داخله مباشرة. لا تكتفِ بنسخ هذا الملف وحده.

المستودع العام هو [presidential-governance](https://github.com/muammed1/presidential-governance)، ويمكن تنزيل [ZIP الإصدار التجريبي](https://github.com/muammed1/presidential-governance/releases/download/v1.1.0-preview.4/presidential-governance-1.1.0-preview.4.zip). النسخة المثبتة مسبقًا تحتاج مراجعة ونسخة احتياطية قبل استبدالها.

## أول مهمة

اختر المهارة من قائمة المهارات في تطبيقك. في Codex CLI/IDE يمكن استدعاؤها بهذا المثال:

```text
استخدم $presidential-governance بالوضع Professional.
راجع المشروع واقترح خطة صغيرة لإضافة تصدير CSV.
المطلوب استكشاف وتخطيط فقط، دون تعديل ملفات أو إطلاق وكلاء.
```

اختر أسلوب التعامل مرة واحدة:

| الوضع | ماذا يتغيّر؟ |
|---|---|
| Professional | تعاون هندسي مباشر. |
| Presidential | أنت صاحب المشروع، والوكيل مستشار يعرض الحالة والتوصية والأثر، ويطلب قرارك عند الحاجة الفعلية. |

قواعد الصلاحيات وسلامة المعمارية والتحقق واحدة في الوضعين. Presidential يحافظ على علاقة صاحب المشروع والمستشار، مع كلام متناسب وألقاب قليلة. سؤال عابر لا يحتاج دورة حوكمة كاملة.

## من الخطة إلى التنفيذ

يراجع الوكيل تعليمات المشروع ومصادر الحقيقة، ويحسم الأسئلة التي قد تغيّر التصميم، ثم يعرض خطة محددة. للمهمة الصغيرة يكفي فحص أثر مختصر؛ للمهمة الكبيرة يلزم توضيح المالكين والعقود والمستهلكين والتبعيات والمخاطر.

بعد قراءة خطة فعلية يمكنك إعطاء موافقة محددة، مثل:

```text
أوافق على plan-v001: نفّذ تصدير CSV واختبارات المستهلكين المتأثرين
داخل مساحة العمل المحلية، وحدّث التوثيق المذكور بالخطة.
لا تطلق وكلاء مستقلين، ولا تثبّت Dependencies، ولا تنفّذ Commit/Push أو نشر.
```

تفعيل المهارة وحده لا يمنح موافقة تنفيذ. الموافقة مرتبطة بالفعل والنطاق والهدف ونسخة الخطة. الموافقة الصحيحة التي ما زالت تغطي العمل لا تُطلب مجددًا؛ التغيير الجوهري يحتاج قرارًا للنطاق المتأثر. تعليمات مشروعك وصلاحيات الأدوات تبقى مطبّقة.

## اختيار المراجعة

Fresh-Context Review اختيارية، وإعدادها الافتراضي `ask-every-time` في مراحل المراجعة المناسبة. يوضح الوكيل كلفتها النسبية قبل الاختيار؛ لا تُحفظ رغبة دائمة إلا بطلب منك.

| الخيار | معناه |
|---|---|
| A | الوكيل الحالي يراجع بالسياق الحالي. |
| B | مراجع واحد بسياق جديد، بعد موافقتك الصريحة على إطلاقه ونطاقه. |
| C | عدة مراجعين بأدوار مختلفة، ضمن تفويض صريح ومحدود. |
| D | تجاوز المراجعة الاختيارية فقط. |

اختيار B/C لا يمنح إذنًا مفتوحًا لإطلاق الوكلاء. السياق الجديد قد يشترك بنفس نظام الملفات وتعليمات المضيف؛ لا يُعتبر عزلًا أمنيًا. نُفّذت تجربة محدودة فعلية: مراجع واحد للخيار B ثم مراجعان بأدوار مختلفة للخيار C، دون توريث المحادثة. هذا لا يثبت عزلًا أمنيًا أو قبولًا سلوكيًا شاملًا؛ التفاصيل في [تقرير التجربة](REVIEW-TRIAL-2026-11-08.md).

قبل التنفيذ يبقى **Implementation Readiness Gate** إلزاميًا: هل القرارات والمدخلات والعقود المؤثرة واضحة ومتوافقة؟ وبعده يبقى **Design-to-Code Drift Detection** إلزاميًا: هل التنفيذ يطابق التصميم المعتمد، وأي انحراف يحتاج موافقة؟ الفحصان يتناسبان مع حجم العمل، واختيار D لا يلغيهما.

## الاستئناف وإدارة الملفات

قل: «كمّل هذه المهمة من آخر نقطة». يستخدم الوكيل ملخصًا صغيرًا للوصول إلى النطاق والقرارات والموافقة الأصلية وآخر تغيير وأدلة التحقق والمتبقي، ثم يراجع التغييرات اللازمة فقط. الملخص أو سجل JSON ليس بديلًا عن الموافقة الأصلية. عند تعذّر استرجاعها بشكل موثوق، يُطلب تأكيد الفعل المتأثر.

احفظ وثائق المشروع وسجلاته داخل مساحة المشروع المسموح بها، خارج مجلد المهارة المثبتة. الأمثلة المرفقة بيانات توضيحية وليست موافقات فعلية. دعم Linear والتفويض اختياري ويتطلب أدوات متاحة وصلاحية مناسبة؛ عند غيابها يمكن استخدام مسودات محمولة دون اختراع معرّفات أو ادعاء تنفيذ.

## الحدود والتحقق

المهارة تعليمات للوكيل، وليست أداة توثيق هوية أو حاجزًا أمنيًا. لا تحتاج Python أو Git أو Linear للاستخدام الأساسي. Python مطلوب فقط للفاحص والاختبارات الاختيارية.

راجع [نتائج التحقق وحدودها](../VALIDATION.md): الاختبارات البنيوية ومحاكاة الوكيل الحالي وتجربة المراجعين الثلاثة أدلة مختلفة، ولكل منها نطاقه وحدوده. نجح مدقق Metadata الرسمي باستخدام اعتماد موجود مسبقًا، دون تثبيت أي Dependencies جديدة. قبل الاعتماد عليها في عمل حساس، جرّب مهمة صغيرة بإشرافك واطلب أدلة على الاختبارات الفعلية.
