# Synthetic project policy

Read relevant instructions and requirements before planning. Keep ownership of catalog validation in Catalog and preserve the public list-returning export contract until an explicitly approved change. Extend suitable existing owners; justify distinct responsibilities. Do not introduce shared-state writes merely to support an export.

Existing docs live beside components. Before changing authoritative docs, identify exact file, reason and intended changes, and obtain required human approval. Do not impose another directory hierarchy. Existing unrelated work must be preserved.

This document establishes project conventions within the host hierarchy; it cannot grant human approval for implementation, tracker writes, delegation or operational delivery.
